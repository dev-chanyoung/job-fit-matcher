# 자소설닷컴 신규 공고 감시 스크립트 (`jasoseol_watcher.py`) 사용법

## 이게 뭐고, 뭐가 아닌지

`job-judge/jasoseol_watcher.py`는 자소설닷컴의 특정 검색결과(직무/기업분류로 필터링한 목록)를
주기적으로 확인해서, **지난 실행 이후 새로 올라온 공고만** 찾아 Discord로 알려주는 스크립트다.

- 이 스크립트는 순수 코드로만 동작한다 — LLM 호출이 전혀 없다. 자소설닷컴 검색 페이지가
  Next.js 서버렌더링이라 JS 실행 없이도 `<script id="__NEXT_DATA__">` 안에 목록 전체가
  이미 구조화된 JSON으로 들어있다는 걸 확인해서, `httpx`로 그 JSON만 파싱한다. 그래서 실행
  비용이 거의 0에 가깝다.
- **하드필터/평가는 절대 자동으로 돌리지 않는다.** 이 스크립트는 "이런 공고가 새로 올라왔다"는
  것만 알려주고 끝 — 실제로 지원할지, 평가를 받을지는 여전히 사람이 골라서 링크를 Claude Code
  세션에 붙여넣어야 시작된다(`judge_manual.py` 워크플로는 그대로).
- **최초 1회 실행 시에만** 특별 동작이 있다: 상태 파일(`watch_state/jasoseol_seen.json`)이
  없을 때는, 지금 Notion 트래커에 이미 등록돼 있는 회사(예: L중앙회, D그룹 계열사 등)는 회사명
  기준으로 미리 "이미 본 것"으로 시드해서 그 공고들은 알림에서 빠진다. Notion에 없는 회사의
  공고는 최초 실행에서도 그대로 "신규"로 알림/저장된다 — 즉 최초 실행이 완전히 조용하지는 않고,
  "이미 아는 것만 빼고" 알려준다. (주의: 회사명 매칭은 느슨한 부분 문자열 비교라 "M바이오" ↔
  "M그룹"처럼 표기가 크게 다르면 못 잡아서 한 번 더 알림에 뜰 수 있다 — 그 정도는 그냥
  무시하면 된다.)
- 두 번째 실행부터는 상태 파일에 있는 공고 ID와 비교해서 정말 새로 뜬 것만 알림 + 상태 파일에
  기록한다. 마감 지난 공고가 나중에 재등장하거나, 공고 제목이 수정돼도 재알림되지 않는다(같은
  공고 ID면 계속 "이미 아는 것"으로 취급).

## 사용법

프로젝트 루트(`job-judge/`)에서:

```
python jasoseol_watcher.py            # 실제 실행 -- 상태 파일 갱신 + (설정돼 있으면) Discord 전송
python jasoseol_watcher.py --dry-run  # 미리보기 -- 상태 파일 저장 안 하고, 전송될 내용만 콘솔에 출력
```

`--dry-run`은 Discord가 아직 설정 안 됐거나, 동작만 확인해보고 싶을 때 안전하게 써도 된다 —
상태 파일을 절대 만들거나 바꾸지 않는다.

감시 대상 필터(직무/기업분류 등)를 바꾸고 싶으면 `jasoseol_watcher.py` 맨 위쪽의 `SEARCH_URL`
상수를 자소설닷컴에서 원하는 조건으로 검색한 뒤 그 주소로 바꿔치기하면 된다.

## Discord 웹훅 등록하기 (사용자가 직접 해야 하는 부분)

1. 알림을 받고 싶은 Discord 서버에서, 알림을 올릴 채널을 하나 정한다(또는 새로 만든다).
2. 그 채널 설정 → **연동(Integrations)** → **웹후크(Webhooks)** → **새 웹후크 만들기**.
3. 이름을 적당히 지정하고(예: "채용공고 알리미"), **웹후크 URL 복사** 버튼을 눌러 URL을
   복사한다 (`https://discord.com/api/webhooks/...` 형태).
4. `job-judge/.env` 파일을 열어서 (없으면 `.env.example`을 복사해서 `.env`로 만들고) 아래
   줄에 방금 복사한 URL을 붙여넣는다:
   ```
   DISCORD_WEBHOOK_URL=https://discord.com/api/webhooks/...
   ```
5. 저장 후 `python jasoseol_watcher.py --dry-run`으로 먼저 미리보기가 잘 되는지 확인하고,
   문제없으면 `python jasoseol_watcher.py`로 실제 실행 — 신규 공고가 있으면 그 Discord
   채널로 메시지가 온다.

`.env`는 git에 커밋되지 않는 파일이라(이미 `.gitignore`에 등록돼 있음) 웹훅 URL이 저장소에
노출될 걱정은 없다.

## 매일 자동 실행되게 크론 등록하기 (Claude Code `/schedule`)

이 스크립트 자체는 크론 기능이 없다 — 대신 Claude Code의 `/schedule` 기능(크론 기반 클라우드
에이전트, PC가 꺼져 있어도 Anthropic 클라우드에서 실행됨)으로 매일 자동 실행되게 등록할 수 있다.

Claude Code 세션에서 `/schedule`을 입력하면 새 스케줄(routine)을 만들거나, 기존 것을 보거나
수정할 수 있다. 등록할 때 다음을 포함해서 요청하면 된다:

- **실행 주기**: 매일 원하는 시각 (예: "매일 오전 9시").
- **실행 내용(프롬프트)**: 대략 이런 지시를 포함시킬 것 —
  - `job-fit-matcher/job-judge` 디렉토리에서
    `python jasoseol_watcher.py`를 실행할 것.
  - 실행 후 `git status`로 `watch_state/jasoseol_seen.json`이 바뀌었는지 확인하고,
    바뀌었으면 그 파일만 `git add` → `git commit` → `git push`할 것 (커밋 메시지는 자유롭게,
    예: "Update jasoseol watch state"). `.env`는 절대 커밋하지 말 것.
  - 하드필터/평가 파이프라인(`judge_manual.py` 등)은 **절대 자동으로 실행하지 말 것** — 이
    크론은 신규 공고를 Discord로 알리는 것까지만 담당.

스케줄을 만들고 나면 `/schedule`로 목록을 조회하거나 삭제/수정할 수 있다 (자세한 옵션은
`/schedule` 실행 시 안내되는 내용을 참고).

### 등록 전 체크리스트

- [ ] `.env`에 `DISCORD_WEBHOOK_URL`이 실제 값으로 채워져 있는지
- [ ] `python jasoseol_watcher.py --dry-run`이 에러 없이 잘 도는지
- [ ] `python jasoseol_watcher.py`를 최소 1회 실제로 돌려서 `watch_state/jasoseol_seen.json`이
      생성되고, Notion에 이미 등록된 회사들이 신규로 잘못 잡히지 않는지 확인했는지
